# Consumer review boundaries

Historical consumer searches and adoption closeouts documented purpose and
ownership; they did not authorize sibling edits or establish every consumer's
current runtime acceptance. Their detailed run diaries and raw archives are
retired under the [evidence cleanup](README.md#retired-raw-evidence).

## Useful conclusions

- Recording belongs to operational instrumentation of the Canic application tree.
  Metrics is not a generic mathematics, report-decoding or validation dependency.
- Applications own sampling, units, labels, reset authorization, instance identity,
  bounded attribution and endpoint exposure. IcyDB's overlapping observations
  and Canic's exclusive accounting remain distinct caller contracts.
- Real instrumentation fixtures and governed persistence are legitimate uses;
  CLI rounding, unrelated diagnostic arithmetic and arbitrary-report decoding
  remain local to their actual owner.
- Canic's adapter owns report DTOs, Wire/TypeScript projection and its shared
  endpoint. An independent deployed host's endpoint cannot silently disappear
  without an owning contract and migration decision.
- Publication, a dependency update, source inspection and a local substitute do
  not establish installed application or retained-codec qualification.

The [current API inventory](../metrics-api.md) and
[extraction contract](../extraction.md) map the concrete owning boundaries.
Observability #130 is closed for the producer cut; remaining consumer acceptance
stays at the relevant owner. No fresh sibling source or private feedback is
exported by this summary, and no stale issue status is inferred from an old search.
