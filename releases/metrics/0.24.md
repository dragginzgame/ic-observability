# Metrics 0.24: Wire 0.13 native schema identity

Metrics 0.24 selects published Wire/Derive 0.13.0. Native schemas for
aggregates, counters, summaries and histograms implement that Wire trait identity.
Consumers composing those values must select one matching Metrics/Wire graph:

```toml
[workspace.dependencies]
ic-metrics = { version = "0.24", default-features = false, features = ["native-wire"] }
ic-wire = { version = "0.13.0", default-features = false, features = ["typescript"] }
```

Use this selection only after a Metrics 0.24 release is published. Registry
Metrics 0.23.2 supplies Wire 0.12 metadata; unchanged local package version fields
do not make this unpublished source selection available to registry consumers.
The [0.23 guide](../../docs/migration-023.md) retains that earlier pairing.

## Canonical Principal and Account

Wire 0.13's `platform-types` feature supplies schemas for canonical
`ic-platform-types` 0.15. Use compatible published Types 0.15.1 when composing
identity-bearing reports. Platform 0.15.2 reexports those same identities; its
`principal` feature suffices for schema-only qualification without runtime/CDK.
The move from Types 0.1 to 0.15 changes Rust identity, so applications must align
their identity supplier as well as Wire. Do not add external-trait bridges or
consumer-owned measurement/identity mirrors.

Principal remains bounded bytes (maximum 29). Account remains owner plus an
optional 32-byte subaccount: absent and explicit-zero subaccounts retain distinct
encoded representations. Metrics' numeric fields, schema shapes, encoded bytes
and canonical malformed-state admission remain unchanged.

## Independent consumers and publication

Defaults still enable `native-wire` only on native targets. Disabling defaults
keeps arithmetic and validated Serde independent of Wire. Recording remains a
separate opt-in, and Wasm excludes Wire even with all Metrics features enabled.
The arithmetic floor remains Rust 1.91 with no allocator requirement.

Metrics itself selects no Types, Platform or endpoint dependency. There is no
endpoint consumer here, so no `ic-wire-endpoint` is introduced. Endpoint hosts
retain their own matching integration acceptance.

Only ic-metrics needs a new publication to supply native Wire 0.13 schemas.
Logging and arithmetic-only consumers do not need a paired release. Sibling
schema generators and persistence adapters own their integration qualification;
a dependency update alone does not establish their acceptance.

[Qualification evidence](../../docs/evidence/wire-0130/README.md) distinguishes
published suppliers from the temporary source-aligned Metrics consumer.
