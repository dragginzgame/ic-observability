# Metrics 0.28: service-owned report schemas

This boundary change implements
[#128 — Remove Metrics' Wire metadata dependency](https://github.com/dragginzgame/ic-observability/issues/128).
Metrics keeps measurement arithmetic, state validation and standard Serde.
Services own frontend/report DTOs, Wire schemas and generated clients. There is
no Metrics-to-Wire or Wire-to-Metrics dependency and no metrics-wire adapter crate.

## Breaking removal

Remove `native-wire` from dependency feature selections and feature forwarding.
`MeasurementAggregate`, `MeasurementCounter`, `MeasurementSummary` and
`MeasurementHistogram<N>` no longer implement Wire's native schema trait.
An enclosing Wire-derived report must project these values into service-owned
fields rather than requiring those implementations. The `recording` feature
remains opt-in; arithmetic and Serde need no default feature suppression.

Keep application schemas and encoded field order/representation at their owner.
Project the same canonical numeric fields when preserving an existing service
format: aggregate count, u128 total, optional maximum and actual-overflow flags;
counter total/flag; summary aggregate/latest; histogram fixed bounds, counts,
overflow, count-loss flags and aggregate. Incoming DTOs must pass canonical
`from_parts` admission before their values enter measurement arithmetic.
Empty versus measured zero, absent versus present values and exact caps versus
actual loss remain distinct. Do not infer lost flags from clipped numbers.

The Serde records retain their names, declaration order and representations,
including u128 totals and fixed-bound arrays. Rust numeric admission, error
precedence, arithmetic and allocator-free behavior are unchanged. No retained
state reset or storage-format conversion is required by this supplier change.
Services independently qualify their codec limits, bytes and generated clients;
Serde stability alone is not proof of any application's protocol compatibility.

## Coordinated adoption

Prepare consumer DTO changes against the existing supported Metrics dependency
with native metadata disabled where practical. Test actual endpoint declarations
and generated/native clients without feature unification masking reliance on the
removed trait implementations. Then adopt the released supplier cut coherently.
These are the existing actionable consumer owners:

- [Blob #113 — Own standalone metrics Wire DTOs](https://github.com/dragginzgame/ic-blob-storage/issues/113).
- [IcyDB #614 — Separate recording types from frontend report DTOs](https://github.com/dragginzgame/icydb/issues/614).
- [Relay #22 — Own private diagnostic Wire DTOs](https://github.com/dragginzgame/ic-relay/issues/22).
- [Storage #154 — Remove Metrics-native schema coupling from qualification](https://github.com/dragginzgame/ic-storage/issues/154).
- [Canic #523 — Deliver tracked Metrics quality through reports and codecs](https://github.com/dragginzgame/canic/issues/523), including its existing primitive MetricValue projection.

Timers' arithmetic use needs no separate schema migration. Platform reads,
labels, attribution, authorization, window identity and persistence remain at
their existing owners. Toko Miner's game-shard dependency also explicitly selects
`native-wire`; its owner must remove that selection when adopting this cut and
qualify its existing report projections. No Toko source changes or acceptance
are included here. Logging has no Wire dependency or release requirement
for this cut. Rust 1.99.1 remains the supported compiler on native and Wasm.
Historical pairing receipts remain historical; Metrics-owned browser/schema
qualification and Node/npm setup are retired from current CI and release gates.
The [verified 0.28.0 delivery](../../docs/evidence/metrics-0280-delivery-20261103.md)
records full release validation, official archive/source verification and exact
registry-consumer acceptance.
